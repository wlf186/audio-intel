# 视频画面检测验证

## 可读步骤验证（presentation-v6）

按时间顺序核对实际代表图，同一视频的三档共享一次候选扫描。均衡全片冷预览包含生成图片的时间。写入量采用 Linux 进程 I/O 计数，耗时为本机单次观测。

| 样例 | 精简 v5 → v6 | 均衡 v5 → v6 | 详细 v5 → v6 | v6 均衡冷预览 | 进程写入 |
|---|---:|---:|---:|---:|---:|
| 13 分 40 秒动画演示 | 129 → 121 | 199 → 189 | 290 → 280 | 48.79 秒 | 14.82 MB |
| 22 分 48 秒网页和真人混剪 | 122 → 109 | 190 → 162 | 276 → 239 | 88.95 秒 | 16.38 MB |
| 约 14 分钟纯 PPT | 30 → 30 | 30 → 30 | 30 → 30 | 30.01 秒 | 4.43 MB |

动画演示 03:49 的完整提问在三档均可见，精简与均衡各留一张；详细档也保留问题出现前的提示。01:34–01:54 的四项揭示保留 1 / 2 / 7 张。混剪 21:59 起的固定机位口播从 9 / 20 / 22 张变为各一张，19:40 起快速翻页仍可看到六种图表及一次回翻。演示中部分重排版面仍会产生多张近似截图。

v5 对应的均衡冷预览分别为 56.10 秒 / 15.52 MB、96.01 秒 / 19.11 MB、29.71 秒 / 4.43 MB。v6 的全片和局部索引合计分别为 78,396、86,769、39,993 字节。不同运行的负载和文件系统缓存会影响秒数。

已有整片索引与均衡档截图时，三段样例切到精简档均复用原图，进程写入为零。切到详细档的额外写入分别为 6.66 MB、8.52 MB、0 字节。预览测试以采样入口调用次数校验跨档命中时无需重扫。下文六小时结果属于历史版本。

## 自动档位验证（presentation-v5）

在同一素材、同一裁剪范围上比较历史 v4 与 v5。三段实录均在本地处理。

| 样例 | 旧版自动 | 精简 | 均衡（默认） | 详细 |
|---|---:|---:|---:|---:|
| 13 分 40 秒动画演示 | 270 | 129 | 199 | 290 |
| 约 14 分钟的 PPT | 30 | 30 | 30 | 30 |
| 约 23 分钟的网页、演示和真人混剪 | 246 | 122 | 190 | 276 |

动画演示中，1:34–1:54 的连续构建在均衡档留下两张图，包含最终状态。两个各一分钟的标注窗口中，旧版和均衡档均命中 18 个状态中的 17 个，同一状态内的额外代表图从 22 张减少到 12 张。另两段素材各抽查 60–175 秒。PPT 的五个内容状态在两个版本均有对应图片；混剪中，两版都保留了网页文章，但都漏掉了快速变化的房间演示等状态。这里的检测目标是稳定的演示内容，连续运动镜头覆盖仍有限。

在首段素材上，均衡全片冷预览耗时 56.10 秒，进程写入 15.52 MB。已有全片索引和均衡档 JPEG 时，精简档耗时约 0.004 秒、写入 0 字节；详细档耗时 6.30 秒、写入 6.66 MB。首次预览三分钟范围耗时 10.60 秒，写入 3.30 MB；同范围切详细档耗时 4.01 秒，写入 4.64 MB。全片与局部索引共 80,665 字节。这里测量的是检测和生成预览图的单次调用，Linux 进程写入量用十进制 MB 表示。真实 GPU 转写另用 PPT 样例完成了一次从接受到结果可读的测试，耗时 65.65 秒。

用以下命令在空输出目录重测档位、耗时和磁盘写入。

```bash
.runtime/api/bin/python scripts/benchmark_video_detection.py details SOURCE.mp4 tmp/video-detail-benchmark
```

## 历史 v4 验证的素材与口径

六小时样片在同一台 Linux 主机、同一块 RTX 4090 Laptop GPU 上通过视频上传接口提交。两种模式均使用真实 Qwen3-ASR-0.6B、音频增强、对齐和说话人流程。上传文件 59,656,221 字节，960×540、4 fps、H.264。每三分钟重复一次幻灯片数字 12% 改为 18%、追加要点、切换长网页及滚动停止的过程，鼠标一直移动。每个周期的短语音后补静音。这个输入用于复现小改动和长时间轴；连续讲话、高清视频和长 GOP 素材需要在目标机器上独立测量。

首次处理耗时从任务接受至结果可读。预览从发出请求至首张候选 JPEG 可读，含轮询耗时。工作目录峰值按周期采样。写入量取 Linux 进程树 I/O 计数差，包括上传和音轨产物；预览独立读取 API 进程计数。主机还有测试负载，数据为单次观测。SSD 固件写放大与 NAND 擦写寿命无法由这些值推算。

## 六小时实测

| 同一输入 | 手动默认 | 自动 |
|---|---:|---:|
| 上传与提交 | 0.39 秒 | 0.40 秒 |
| 任务接受至完成 | 434.98 秒 | 387.38 秒 |
| 其中视频分析阶段 | 151.83 秒 | 97.82 秒 |
| 代表图 | 360 张 | 480 张 |
| 保留的检测索引或特征缓存 | 168,275,952 字节 | 739,579 字节 |
| 采样工作目录峰值 | 1,551,662,183 字节 | 1,384,139,902 字节 |
| Linux 服务进程树写入 | 1,814,609,920 字节 | 1,765,167,104 字节 |

自动模式额外捕获了 120 个周期中的数字替换，新增要点合入同一状态最后一张稳定截图。两种模式都保留了滚动前后的网页。自动任务测量期间，同一隔离服务也处理了手动预览，其 I/O 会计入进程树总量。缓存体积、临时空间峰值与累计写入分别统计。

| 已完成任务上的预览 | 开头 3 分钟 | 中间 3 分钟 | 末尾 3 分钟 | 整片 |
|---|---:|---:|---:|---:|
| 自动，复用同版本结果 | 0.31 秒 | 0.31 秒 | 0.31 秒 | 0.31 秒 |
| 手动，变化比例由 3% 调为 1%，读取特征块 | 1.35 秒 | 1.35 秒 | 1.35 秒 | 102.88 秒 |

三次自动局部预览各写入 20 KiB；手动局部预览为 236 KiB、2.33 MiB、312 KiB。全片预览自动约 196 KiB，手动约 74.66 MiB。自动全片时间对应已有快照的场景。缓存缺失、版本改变或首次用自动模式分析历史任务时需要读取源视频。

## 画面质量

人工按视频时间标注稳定内容状态。每格为“命中状态数 / 标注状态数；同一状态内多出的代表图数”。过渡期或标注空隙中的画面另计。手动默认使用 3%、1 秒，手动高灵敏使用 0.5%、1 秒。

| 真实录屏片段 | 手动默认 | 手动高灵敏 | 自动 |
|---|---:|---:|---:|
| 字幕频繁变化的 PPT，30–90 秒 | 3/3；0 | 3/3；12 | 3/3；0 |
| 深色演示，逐步构建图示，405–465 秒 | 7/7；5 | 7/7；11 | 7/7；10 |
| 同一深色视频的另一段，605–665 秒 | 7/11；2 | 9/11；2 | 10/11；10 |

最后一段在实现定稿后先标注再检测，包含引文高亮、卡片文本替换和连线图。过渡或标注外画面三种模式分别为 2、2、4。自动模式在这里多找回三个标注状态，也需要阅读者面对更多重复图。三段共三分钟，不宜据此估计整门课程的漏检率或每小时重复数。未提交用户录屏及截图。

## 复现

在隔离服务中使用仓库的可执行基准脚本，工作目录需有空间容纳六小时的播放与增强音轨。首次生成样片时指定一段本地短语音。用于测试的两个服务实例与日常服务使用各自的端口、数据、临时和运行目录。

```bash
mkdir -p tmp/video-validation
.runtime/asr/bin/python scripts/benchmark_video_detection.py fixture tmp/video-validation/six.mp4 --audio LOCAL_SHORT_SPEECH.wav
.runtime/api/bin/python scripts/benchmark_video_detection.py service tmp/video-validation/six.mp4 tmp/video-validation/jobs --url "$AUDIO_INTEL_BASE_URL" --run-dir "$AUDIO_INTEL_RUN_DIR" --work-dir "$AUDIO_INTEL_TEMP_DIR"
.runtime/api/bin/python scripts/benchmark_video_detection.py previews JOB_ID tmp/video-validation/previews --url "$AUDIO_INTEL_BASE_URL" --api-pid-file "$AUDIO_INTEL_RUN_DIR/api.pid" --work-dir "$AUDIO_INTEL_TEMP_DIR"
.runtime/asr/bin/python scripts/benchmark_video_detection.py quality SOURCE.mp4 labels.json tmp/video-validation/quality
```

`labels.json` 使用媒体秒，例如 `{"range":[30,90],"states":[{"interval":[30,52]},{"interval":[53,76]},{"interval":[77,90]}]}`。每次测量选择新的输出目录，分别保存逐段结果与计数。
